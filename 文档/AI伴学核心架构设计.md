# AI 伴学核心架构设计（四步闭环）

> 2026-08-28 · 基于课堂思路整理的可执行方案
> 目标：AI 智能体通过「长期记忆 + 多模态理解」持续认知每个学生，给出越来越贴合的建议、计划与测试。

---

## 0. 总体架构：四步闭环

```
┌─────────────────────────────────────────────────────────────┐
│                    学生（文字 / 语音 / 图片）                    │
└──────────────┬──────────────────────────────┬──────────────┘
               ▼                              ▼
      ┌───────────────┐             ┌──────────────────┐
      │  ① 首次诊断    │             │  ③ 拍照改卷等增强  │
      │  （画像建立）   │             │  （多模态理解）    │
      └──────┬────────┘             └────────┬─────────┘
             ▼                              ▼
      ┌──────────────────────────────────────────────┐
      │  ② 长期记忆层（本项目核心）                       │
      │  ┌──────────┐  ┌──────────┐  ┌──────────────┐ │
      │  │ 结构化数据库│  │ 向量知识库 │  │ 画像 Profile  │ │
      │  │ (SQLite)  │  │(Embedding)│  │ (滚动更新)    │ │
      │  └──────────┘  └──────────┘  └──────────────┘ │
      └──────────────────┬──────────────────────────────┘
                         ▼
      ┌──────────────────────────────────────────────┐
      │  AI 伴学智能体（模型网关：spark/deepseek/qwen/│
      │               minimax/mock）                  │
      │  → 生成个性化计划 / 题目 / 建议 / 改错反馈      │
      └──────────────────────────────────────────────┘
```

- ① 诊断 → 写入 ② 记忆层 → ② 支撑 ③④ 的个性化输出
- ④ UI 打磨与自评：让产品「可持续进步」

## 1. 第一步：全方位诊断画像（建立用户认知）

### 1.1 诊断环节设计（不只有题目，含交流谈心）

| 环节 | 内容 | 形式 | 记录到 |
|---|---|---|---|
| 基础信息 | 姓名/年级/学校/是否偏科 | 选择题 | 数据库 students |
| 学习习惯 | 每天可学时长/喜欢早上还是晚上学 | 选择题 | 数据库（习惯字段） |
| 兴趣偏好 | 喜欢的科目/动画/游戏（用于激励话术） | 选择题+自由输入 | 画像 knowledge |
| 目标期望 | 想提高哪科/想考多少分 | 自由输入 | 画像 goals |
| 心理状态 | 最近学习压力/是否怕数学 | 谈心式问答（AI 引导） | 画像 emotion_history |
| 能力初测 | 六类诊断题（口算/应用题/写古诗/阅读/中选英/连词成句） | 做题 | 数据库 daily_diagnosis |

### 1.2 测试题维度（跟教材年级走，已具备）

| 学科 | 维度 | 生成器 | 状态 |
|---|---|---|---|
| 数学 | 口算 | generate_mental_math_all | ✅ 已有 |
| 数学 | 应用题 | generate_app_questions_all | ✅ 已有 |
| 语文 | 写古诗（默写） | generate_chinese_poem | ✅ 已有 |
| 语文 | 阅读题（选下句/理解） | generate_chinese_reading | ✅ 新增 |
| 英语 | 看中文选英文 | generate_english(reverse=False) | ✅ 已有 |
| 英语 | 连词成句 | generate_english_sentence | ✅ 新增 |

### 1.3 画像更新规则（持续认知的关键）

```
每次交互（做题/聊天/拍照）→ 提取事实 → 更新 Profile（数据库）
  ├─ 掌握度 mastery（按知识点聚合，滚动更新）
  ├─ 弱项 weakness（正确率 < 60% 的维度）
  ├─ 习惯/偏好/情绪（聊天中提取）
  └─ 长期记忆 → 写入向量知识库（供语义检索）
```

> **讨论点**：诊断频率 = 每天一次轻量诊断（已做）+ 每周一次深度画像更新（待做）。

## 2. 第二步：长期记忆知识库系统（核心）

### 2.1 数据分层：**数据库 vs 知识库**

| 数据 | 存哪里 | 理由 | 检索方式 |
|---|---|---|---|
| 学生基础信息/年级 | 数据库 | 结构化、强一致 | SQL |
| 练习记录（题/对错/用时） | 数据库 study_log | 高频写、需聚合统计 | SQL GROUP BY |
| 错题本（次日复习） | 数据库 mistakes | 结构化、定时到期 | SQL |
| 每日诊断结果 | 数据库 daily_diagnosis | 日期索引、覆盖更新 | SQL |
| 课程进度 | 数据库 course_progress | 简单状态 | SQL |
| 用户画像（mastery/weakness/goals） | 数据库 students | 需实时读 | SQL JSON |
| **聊天对话记录** | **向量知识库** | 非结构化、需语义检索 | 向量相似度 |
| **语音转写文本** | **向量知识库** | 同上 | 向量相似度 |
| **图片/拍照内容理解** | **向量知识库**（图片→描述文本→向量） | 多模态，需语义 | 向量相似度 |
| **用户长期事实/偏好/事件** | **向量知识库** | 散落对话中，需聚合 | 向量+关键词混合 |
| 模型调用上下文（供生成） | 向量知识库（top-k 召回） | 快速匹配 | 向量 |

**一句话原则**：
- **数据库 = 事实**（对错、进度、时间、状态）——可枚举、可统计、要精确
- **知识库 = 认知**（说了什么、感受如何、喜欢什么）——非结构化、要语义理解

### 2.2 知识库选型与实现

| 方案 | 选型 | 说明 |
|---|---|---|
| 向量存储 | **ChromaDB（本地起步）** | 轻量、Python 原生、零运维；后续量大可迁 Milvus/腾讯云向量库 |
| 向量模型 | **minimax Embedding API**（`embedding-1`） | 已有 minimax 网关基础，加 embedding 通道 |
| 语义切分 | 对话按「用户话轮」切分，每条 1 个 chunk + 元数据 | student_id / 时间 / 类型（chat/voice/image）|
| 记忆管理 | 每用户一个 collection；写入时带时间戳 | 检索：student_id 过滤 + top-k 向量召回 |

### 2.3 用户记忆结构（3 层）

```
① Profile（数据库，实时可读）      → 当前状态：年级/掌握度/弱项/今日是否已诊断
② Facts（向量库，长期事实）        → 喜好/目标/家庭信息/习惯（从对话抽取）
③ Episodes（向量库，事件记忆）     → 某天发生了什么：诊断结果/拍照练习/情绪波动
```

**检索匹配**：AI 生成建议前 → 向量召回该用户相关记忆 top-8 → 拼进 prompt（记忆增强）→ 生成个性化内容。

### 2.4 参考开源训练模型（用户提到）

- 长期记忆 Agent：**MemGPT / Letta**（分层记忆：main context + external memory）
- 用户画像：**LangChain 记忆模块 / Reflexion**
- 教育测评：**EduPlanner 类个性化学习路径研究**
- 用法：参考其记忆分层与检索策略，不直接搬模型（本项目用 API 网关 + 本地记忆层）

## 3. 第三步：增强功能（拍照改卷 + 多模态记录）

### 3.1 AI 智能改卷（拍照判对错）

```
学生拍照练习页 → 上传图片
   ├─ 视觉理解（minimax vision / 腾讯 OCR）→ 提取题目+学生答案
   ├─ 判题（本地规则 or LLM 判对错）
   ├─ 写入数据库（practice_records：图/题/对错/时间）← 事实
   ├─ 写入向量库（图片描述+错题解析）← 认知
   └─ AI 生成改错建议（召回该生近期错题 → 生成讲解）
```

### 3.2 数据落库划分（拍照场景）

| 数据 | 存哪里 | 说明 |
|---|---|---|
| 原始图片 | 本地文件/对象存储（文件系统） | 路径存数据库 |
| 判题结果（题/对错/科目） | 数据库新表 practice_records | 结构化、可统计 |
| 图片理解描述 + 错因 | 向量知识库 | 语义检索 |
| 改错建议 | 数据库（回显）+ 向量库（积累） | 双写 |

### 3.3 语音/图片/视频统一入口

所有输入先过**理解层**：
- 语音 → ASR 转文字 → 文字进向量库
- 图片 → 视觉模型描述 → 描述进向量库（原文留档）
- 视频 → 关键帧抽帧 → 同上
- 文字 → 直接进向量库

> 理解层统一后，AI 只需面对「文字 + 向量记忆」，多模态能力都收敛在入口。

### 4.2 可持续进步机制（自评闭环）

```
每次学习后 → 记录效果（正确率变化/用时）→ 周报对比
  → 若某维度连续 3 天下降 → AI 主动调整计划（降低难度/换题型/谈心）
  → 若持续进步 → 提升难度，更新画像
```

**产品自验指标**：
- 学生画像准确度（预测 vs 实际表现）
- 推荐命中率（推荐题目的正确率分布）
- 错题复习完成率（次日是否回来复习）
- 留存（每日是否继续诊断）
