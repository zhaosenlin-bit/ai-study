分支：`feature/web-integration-demo`  
主责目录：`apps/web/`、`docs/demo/`、`tests/e2e/`  
目标：把 A/B/C/D 的能力变成评委能看懂、老师能验收、学生能操作的完整 Demo。

## 1. 你负责什么

1. 前端项目骨架和页面。
2. 学生端体验设计。
3. 家长端报告页面。
4. 三科演示流程整合。
5. 端到端测试和录屏脚本。
6. PPT/视频素材整理。

## 3. 必做页面

1. 学生首页：今日任务、连续学习天数、三科掌握度。
2. 诊断页：题目卡片、答题、进度、提交。
3. AI 伙伴对话页：显示引导问题、学生回答、提示层级。
4. 学习路径页：三科知识点路径图，突出薄弱点。
5. 错题本页：错因标签、复习到期、重新作答。
6. 家长报告页：掌握度雷达图、错因统计、下周建议。
7. 演示控制台：一键切换 demo 学生和三科流程。

## 4. 体验要求

- 第一屏直接进入产品，不做营销落地页。
- 小学生界面按钮大、文案短、反馈明确。
- 家长端更克制，重点是数据和建议。
- 所有接口都先支持 mock，再接真实 API。
- 页面上不能出现“这是功能说明”式的大段说明文字。
- 移动端和桌面端都不能有文字重叠。

## 5. API 使用规则

只能按 `docs/api/openapi-contract-v0.yaml` 调接口。

如果字段不够用：

1. 先在群里说明场景。
2. 提 PR 修改 OpenAPI。
3. 等角色 A 确认后再改页面。

## 6. 演示脚本结构

3-5 分钟视频建议：

1. 15 秒：痛点，小学生三科学习薄弱点不一样，家长不知道怎么补。
2. 30 秒：学生登录，AI 伙伴发起三科诊断。
3. 60 秒：数学错题分步引导，展示不直接给答案。
4. 45 秒：语文古诗/阅读情境化追问。
5. 45 秒：英语错词进入复习计划或情景对话。
6. 30 秒：学习路径变化和错题本。
7. 30 秒：家长报告和技术架构。

## 7. 验收标准

- 浏览器能完整跑通三科 demo。
- 没有空页面和明显假按钮。
- API 失败时有友好提示。
- 至少有 1 个端到端测试脚本。
- 能录出 3-5 分钟演示视频素材。
- 路演 PPT 截图素材完整。
