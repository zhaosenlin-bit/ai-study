# A-E 角色分工确认看板

用途：课堂上由老师确认五位同学的角色。确认后，把“待填姓名”替换为真实姓名，并要求每位同学在群里发送确认消息。

项目名：`ai-study`

## 1. 角色确认表

| 角色 | 待填姓名 | 分支 | 负责内容 | 第一份提交必须有什么 |
| --- | --- | --- | --- | --- |
| A | 待填姓名 | `feature/agent-core` | 后端、Agent、接口、学生画像、路径规划 | `/api/v1/health`、mock 诊断接口、Schema 草案 |
| B | 待填姓名 | `feature/subject-math` | 数学知识点、题库、错因、数学 Prompt | 5 个知识点、5 道题、1 个 Prompt |
| C | 待填姓名 | `feature/subject-chinese` | 语文知识点、古诗/阅读/表达题库、语文 Prompt | 5 个知识点、5 道题、1 个 Prompt |
| D | 待填姓名 | `feature/subject-english` | 英语词库、题库、复习调度、英语 Prompt | 5 个词汇节点、5 道题、1 个 Prompt |
| E | 待填姓名 | `feature/web-integration-demo` | React 前端、家长端、演示脚本、联调 | 首页、诊断页 mock、演示控制台雏形 |

## 2. 角色不是孤岛

| 谁依赖谁 | 依赖内容 | 如何避免等待 |
| --- | --- | --- |
| E 依赖 A | 接口字段和返回格式 | A 先给 mock，E 先写假数据页面 |
| A 依赖 B/C/D | 三科题库和知识图谱 | B/C/D 先交最小 JSON 样例 |
| B/C/D 依赖 A | 统一数据格式 | 先按 OpenAPI 和样例字段写 |
| 全组依赖 E | 演示路线和截图 | E 先出 3-5 分钟演示脚本 |

## 3. 每位同学确认角色后要发的话

```text
我是角色 X，负责 ______。
我的分支是 ______。
今晚我先提交 ______。
我需要 ______ 同学配合 ______。
我目前最担心的风险是 ______。
```

## 4. 老师检查口径

老师不只检查“有没有写代码”，还检查：

- 是否按自己的分支提交。
- 是否按自己的目录提交。
- 是否能说清楚自己的模块如何接入完整闭环。
- 是否有可运行或可读取的最小样例。
- 是否把阻塞讲清楚，而不是等到最后一天。
