# A-E 角色分工确认看板

用途：课堂上由老师确认五位同学的角色。确认后，把“待填姓名”替换为真实姓名，并要求每位同学在群里发送确认消息。

项目名：`ai-study`

## 0. 领取规则先说清楚

每位同学领取的不是单独一份角色文档，而是一组文档：

1. 全组共读：`README.md`、总 PRD、课堂讲义、技术栈指南、文档领取指南、Git 协作规范、OpenAPI。
2. 角色文档：A-E 中自己负责的那一份。
3. 方案模板：今晚创意方案按 `docs/proposals/student-proposal-template.md` 写。

具体阅读顺序以 `docs/03-document-reading-and-versioning-guide.md` 为准。

## 2. 角色不是孤岛

| 谁依赖谁 | 依赖内容 | 如何避免等待 |
| --- | --- | --- |
| E 依赖 A | 接口字段和返回格式 | A 先给 mock，E 先写假数据页面 |
| A 依赖 B/C/D | 三科题库和知识图谱 | B/C/D 先交最小 JSON 样例 |
| B/C/D 依赖 A | 统一数据格式 | 先按 OpenAPI 和样例字段写 |
| 全组依赖 E | 演示路线和截图 | E 先出 3-5 分钟演示脚本 |

## 2.1 体验统一口径

所有角色都要围绕同一个产品画面交付：中间是 AI 精灵和学习任务，左侧边缘是三科入口和任务，右侧边缘是错题本、徽章、家长报告。三科内容和后端接口都要服务这个体验，不要各自做成孤立页面。

## 3. 每位同学确认角色后要发的话

```text
我是角色 X，负责 ______。
我已经阅读：README、总 PRD、课堂讲义、技术栈指南、文档领取指南、Git 规范、OpenAPI、我的角色文档。
我的分支是 ______。
今晚我先提交 ______。
我需要 ______ 同学配合 ______。
我目前最担心的风险是 ______。
```

## 4. 老师检查口径

老师不只检查“有没有写代码”，还检查：

- 是否按自己的分支提交。
- 是否按自己的目录提交。
- 是否能说清楚自己的模块如何接入完整闭环。
- 是否有可运行或可读取的最小样例。
- 是否把阻塞讲清楚，而不是等到最后一天。
