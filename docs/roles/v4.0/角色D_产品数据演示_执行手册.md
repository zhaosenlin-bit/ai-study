## 四、技术模板（可直接复制）

### 4.1 SQLite 三表（简化 DDL 要点）

| 表 | 关键字段 |
|---|---|
| students | student_id PK、name、grade、weak_points JSON、strong_points JSON、learning_style、emotion_state |
| mistakes | mistake_id PK、student_id FK、question、student_answer、correct_answer、error_type、knowledge_point_id、resolved、review_count、next_review_at |
| knowledge_points | kp_id PK、name、grade、subject、difficulty、prerequisites JSON、description |

### 4.2 5 个虚拟学生档案

| 学生 | 年级 | 薄弱点 / 风格 |
|---|---|---|
| 小明 | 4 | 分数运算弱 · 视觉型 |
| 小红 | 3 | 应用题建模弱 · 听觉型 |
| 小刚 | 5 | 英语词汇弱 · 动觉型 |
| 小丽 | 4 | 古诗理解弱 · 视觉型 |
| 小宇 | 3 | 计算粗心 · 听觉型 |

### 4.3 10 个测试场景（覆盖四大能力）

| 能力 | 场景 |
|---|---|
| 诊断 ×3 | 新用户首诊 / 复诊（带历史画像）/ 跨学科主题诊断 |
| 路径 ×2 | 薄弱点推荐路径 / 前置未掌握时回退 |
| 干预 ×3 | 概念缺失 / 计算粗心 / 情绪焦虑（切换导师身份） |
| 反思 ×2 | 5 轮对话后调整路径 / 错题复习提醒 |

### 4.4 演示脚本（3~5 分钟）

| 时间轴 | 画面 / 操作 | 旁白要点（一句） |
|---|---|---|
| 0:00-0:15 | 开场：项目名 + 覆盖学段 | “小学全科 AI 伴学伙伴，用跨学科主题项目带学习” |
| 0:15-1:30 | 登录 → 选“太空探险” → 做 3~5 道诊断题 | “先诊断：孩子哪里强、哪里弱” |
| 1:30-2:00 | 展示画像 + 薄弱点 + 路径推荐 | “系统根据错因规划个性化路径” |
| 2:00-3:15 | 卡在分数加法 → AI 引导 2~3 轮 → 答对 | “卡住时 AI 换身份引导，不直接给答案” |
| 3:15-4:00 | 复盘：错题本更新 + 经验值 + 雷达图 | “每轮学习都沉淀到长期记忆” |
| 4:00-5:00 | 收尾：家长端报告 + 商业模式一句话 | “家长看得懂，产品能落地” |

### 4.6 评委 Q&A 预案（10 题）

| 问题 | 回答要点 |
|---|---|
| 为什么做小学全科而非单科？ | 差异化 + 跨学科主题场景 + 赛道竞争小 |
| 学习路径的科学性依据？ | 教材大纲结构化 + 前置关系图谱 + 错因归因 |
| 大模型幻觉怎么办？ | RAG 限定知识库 + Prompt 约束 + 低年级内容人工审核 |
| 数据从哪来？ | 公开教材大纲 + 自建题库 50+ + 5 虚拟学生演示 |
| 怎么商业化？ | 家长订阅 + 学校 B 端，先做家长端报告 |
| 未成年人合规？ | 不收集真实身份、最小化数据、家长知情 |
| 和 Khanmigo 的区别？ | 本土教材 + 三科跨学科 + 中文场景 |
| 技术难点？ | 路径决策 + 记忆长期一致性 + 多角色切换 |
| 如果只剩 3 天会砍什么？ | 砍家长端和多角色，保闭环演示 |
| 最大风险？ | API 限流与题库质量，已有备用方案 |
