## 4. 与 v1.0 基线的差异

### 4.1 团队分工变化

| v1.0 基线 (4 人) | v0.3 仓库 (5 人) |
| --- | --- |
| A: Agent 架构 + API | A: Agent 后端 + 接口 (保持) |
| B: 大模型 + 知识库 (统一) | B: 数学模块 (拆分) |
| C: 前端 + 体验 | C: 语文模块 (拆分) |
| D: 产品 + 数据 + 演示 | D: 英语模块 (拆分) |
| --- | E: 前端体验 + 联调 + 演示 (新增，从 D 接管前端) |

### 4.2 评估

优点
- 5 人按学科拆分，每个学科负责人更聚焦自己的领域知识
- B/C/D 三人可以并行交付各自学科的题库 / Prompt / 知识图谱
- E 单人扛前端 + 联调 + 演示，路径最清晰

风险
- 5 人比 4 人多 1 人，沟通成本上升
- 学科负责人 (B/C/D) 缺少跨学科协调人——若需要火星基地这种跨学科项目，没人牵头
- E 的工作量可能过大 (前端 + 联调 + 演示 + 视频 + PPT)

### 4.3 产品定位差异

| 维度 | v1.0 基线 | v0.3 仓库 |
| --- | --- | --- |
| 学习入口 | 今日任务 (每日 3 个) | 今日任务 (一致) |
| 跨学科 | 未强调 (潜在) | 未强调 |
| 长期记忆 | 强调 (小星日记、人格化) | 强调 (emotion_state、mastery map) |
| 人格化 | 强调 (小星 4 情绪) | 弱 (紫色星星，无情绪系统) |
| 主题项目 | 强调 (火星基地) | 未涉及 |
| 评分对齐 | 30+25+20+15+10 | 一致 |

### 4.4 我的判断

仓库现在走的是稳的路线——三科并列、闭环完整、Mock 数据成熟，能保证 9 月 9 日提交且不出事故。

但缺少了 v1.0 基线和星图探险家方案里提到的跨学科主题项目和 AI 同伴人格化这两大差异化亮点。这两项如果做到，有望在 30 分创新体验和 25 分自适应策略上拉开差距。
